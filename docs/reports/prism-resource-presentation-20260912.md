## 前端改动

沿用已确认的 V6 结构、玻璃材料和六类账号分组。本批没有调用外部设计模型或更换视觉方向。

| 入口与流程 | 改动 |
|---|---|
| 全部账号、授权、账号详情、运行状态 | 邮箱/姓名与实际渠道作为标识；不显示凭据 ID、上游 ID 或八位生成编号；关联信息显示人类名称 |
| AI 提供商、接口、账号与绑定维护 | 列表、编辑和删除标题统一名称；绑定按协议/主机及账号身份选择，包含未绑定接口 |
| 模型与路由、候选、模型目录 | 路由按名称载入；候选选择实际接口；详情、编辑、删除与创建回执不显示测试主键 |
| API 密钥与访问组 | 访问组、路由授权选择、编辑与吊销确认使用名称；密钥公开前缀保留其识别用途 |
| 请求日志与失败、请求尝试详情、用量和计费 | 资源引用统一格式；筛选选择名称，旧 query 和已删除资源的精确筛选仍可使用 |
| 运行诊断、Explain、通道诊断与出口 | 提供商、接口、账号与路由使用资源选择；出口引用与删除提示清理旧名称 |
| 配置、差异、审计与全局上下文 | 来源、发布/回滚确认与详情使用统一显示规则；自动编辑副本显示“配置副本” |
| 仪表盘与设置 | 保持现有功能与主导航；共享名称组件生效，三个尺寸入口检查通过 |

统一规则优先使用已观测身份和业务名称；旧阶段前缀、测试标记、时间戳及随机摘要不会再生成另一串编号。
已有不可编辑的主键改为显示名称、隐藏原表单值。选择器调用现有权威接口，分页有界，保留失败/重读入口。
历史筛选有“指定历史资源…”入口：输入真实引用并应用后恢复可读标签，兼容不存在于当前配置中的对象。

`IdentityDetails` 的“技术标识”改为折叠的“关联信息”，不再直接打印旧 ID。
需要精确排查时可明确点击“复制内部引用”；该操作复制原主键，不冒充复制邮箱。
原 ID 继续用于 API、URL、缓存、隐藏表单值与操作定位，也保留在原始审计/导出及机器 JSON 导入中。
这次没有批量重命名生产主键，也没有伪造另一套“生产 ID”。

真实邮箱、电话、公开模型的 exact name、模型别名、请求/attempt 追踪号与 revision 不做盲目替换。
验收专门使用 `p12-member@example.test` 证明合法身份不会因看似前缀而被删改。
同邮箱的不同合法授权仍独立保留；本次生产单例是服务端核实同一 grant 后的配置整理结果，
不是在前端无条件隐藏重复行。
