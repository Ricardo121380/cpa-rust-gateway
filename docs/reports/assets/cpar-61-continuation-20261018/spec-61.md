经逐字段审查的 Build 元数据完整加密留存后，标准 Responses 的 JSON 与 SSE 均能准确交付回答、摘要和多轮工具调用，并在不兼容、取消或持久化失败时准确拒绝或结束。

覆盖 #58 用户故事 16, 17, 18, 19, 20, 22, 23, 25, 26, 27, 28, 29, 34, 36, 37, 40, 41, 42, 43, 44, 45, 46, 49, 56；验收场景 T02, T03, T04, T06, T07, T08, T09, T10。

本票承接 #58 的已确认范围；实际开工须有用户明确指令。真实账号、收费请求、共享服务与发布部署分别遵守既有授权边界。

各验收组必须全部满足；可分别记录进展，任一必需组受阻时整票不能标完成。

执行条件：实际字段的语义依据是完成条件；缺少依据时保留明确 BLOCKED。研究与实现不附带真实推理授权。

## Acceptance criteria

### Responses JSON

- [ ] 先明确实际字段的来源渠道、位置、值形状、适用协议/模式、语义依据及标准语义不受影响的理由；覆盖响应根对象、item/part 与 Usage，不仅移除 Usage 扩展检查。
- [ ] 从公共 Responses JSON 入口贯通真实应用装配、Build 解码、标准投影、exact Attempt 加密保存和授权读回；成功 bytes 交付前完成所承诺证据持久化及投影核对。
- [ ] 回答、工具名称/ID/完整参数、结果关联、原生 summary 与已知 Usage 保持；覆盖至少两次相关工具循环及中间问答，所有成功场景都核对模型身份。
- [ ] 对发送前可判定的已知不兼容请求控制，经公共入口准确拒绝，独立受控接收数为零；不能先发送一次再以响应失败代替请求准入。
- [ ] 未知字段、未审查形状、身份/顺序/终态矛盾、精度损失和加密写入失败不产生成功；相同请求不透明重发，不以保存任意 JSON 为放行依据。
- [ ] 普通 metadata 与 reasoning 语义保持区分；本票不应用 Messages summary 省略规则，不加入 native-v1 封套。
- [ ] 至少一项实际获准字段有适用证据，并通过公共正反例和完整读回；测试专用允许名单或纯合成字段不能冒充实际字段资格。没有适用证据则保留 BLOCKED，不能关闭本票。
- [ ] 原未解释 Usage object 和真实模型别名不因其他字段获准而自动解除阻断；本票不是原真实样本或首版客户端的真实通过证明。

### Responses SSE

- [ ] 复用本票 JSON 路径的已审查字段与标准语义，贯通公共 SSE、实际 Build 装配、增量解码和证据写入；不形成第二套字段准入规则。已知不兼容请求在发送前拒绝，独立受控接收数为零。
- [ ] 使用真实分片的文本、summary 与工具参数事件，覆盖任意分块和合法交错；工具参数完整合法才成为可执行调用，增量/终态内容与 JSON 结果一致。
- [ ] 成功终态之前完成证据持久化确认；HTTP headers 已发送后遇到写入失败、确认超时、未知字段或终态冲突时，以合法且唯一的失败收口。
- [ ] 取消、断流和超时停止后续工作并释放占用，不为保存证据继续 read-ahead；已经验证的 Usage 保留，未完成信息标明完整性，不制造成功记录。
- [ ] 独立接收数和 Attempt/Usage/账本核对证明无语义输出后的重试、额外发送或重复计数；已知计数与非结算费用边界保持。
- [ ] 至少两次工具循环与后续问答经过公共 SSE；原未获准字段仍拒绝，既有标准 JSON 行为回归。
