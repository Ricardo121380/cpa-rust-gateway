客户端的公共模型、实际选中的上游模型和 Build 返回的原生模型能够逐次对应；缺失、未知或矛盾不会被标准响应中的模型名称掩盖。

## Acceptance criteria

- [ ] 通过公共 Responses 的 JSON/SSE 请求核对 public、actual upstream、native 三段身份，采用字面等值或预先冻结且范围匹配的可信别名证明。
- [ ] 原生模型字段的缺失、类型错误、响应阶段矛盾和不适用别名分别得到安全且可辨的失败；不将路由提供的公共名称当作原生返回证据。
- [ ] 发送前已知的模型请求不兼容必须在发送前拒绝，独立受控接收数为零；原生响应到达后才发现的身份问题不触发修复后重发、账号/模型切换或透明 fallback，以接收数证明没有附加推理。
- [ ] 保留现有凭据/租约/配置/渠道身份边界；标准输出、失败和诊断归属于实际请求，不借读取当前 inventory 补造历史事实。
- [ ] 使用明确标为合成的字面等值、适用别名、范围不符与矛盾正反例验证机制；原真实样本的别名仍 UNKNOWN，不改旧 oracle，也不要求本票获取新的真实预算。
- [ ] 范围仅为模型身份行为及对应契约，不顺带放开普通元数据或改变 Usage、reasoning、重试与计费规则。
