## Acceptance criteria

- [ ] 覆盖 openai-compatible、anthropic-compatible、kimi-api、grok.official 的 API 预设；空配置无需预建服务、接口或绑定。
- [ ] 适用官方默认值可用，兼容地址／协议及必要地区／代理在当前表单完成；已有自定义设置不被覆盖。
- [ ] 按渠道、授权方式、所有权和连接条件判断：无匹配创建、唯一匹配复用、多匹配就地选；名称相同不构成合并证据。
- [ ] 沿用合并核对及 revision 规则，完整展示保存／连接／生效；失败保留已确认结果，可从当前任务继续。
- [ ] 权限选择不阻塞接入，已有权限保留，新模型默认不开放；不隐式发推理测试或覆盖已有路由。
- [ ] 在现有提供商表单上可独立演示；入口分类改造不是执行层前置，最终与三类入口集成。四类预设的 HTTP／EgoLite 正反例通过。
- [ ] 记录受影响行为的高层本地验证、必要的 EgoLite 产品验收与审查证据；静态存在、fixture、真实渠道和生产结论分开，结果使用 PASS／FAIL／NOT_RUN／BLOCKED。
- [ ] 保留账号／渠道／权限及数据边界；涉及权威管理契约时单向同步生成客户端，遵守既有前后端归属与跨边界记录；必要 ADR 与相关陈旧测试入口随本切片修正。
- [ ] 在实际 checkout 上复核范围，完成适用 Task／Phase 门槛；本票不自动授权真实账号、收费请求、服务变更或部署，具体外部操作以已明确目标和范围为准。
