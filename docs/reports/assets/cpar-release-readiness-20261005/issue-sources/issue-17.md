[实施规格 #9：CPAR 现有渠道可靠性与管理体验收敛](https://github.com/Ricardo121380/cpa-rust-gateway/issues/9)

## What to build

普通与原生账号重复导入保留身份和设置，批量部分失败后只处理失败项，不重放结果未知的项目。

实施编号 CPAR-08；实施批次：A。覆盖用户故事 18, 19, 20, 21, 22, 23, 52, 88；验收场景 T02, T04, T12。

## Acceptance criteria

- [ ] 可靠同渠道同账号的新授权更新原项，相同内容幂等；不按显示名称猜身份、不跨渠道合并。
- [ ] API Key 无法证明人类身份时只用可证明的材料／目标一致性，不编造账号身份；身份冲突拒绝覆盖，未知需要核对。
- [ ] 重复导入保留连接、停用意图、模型权限及自定义设置；既有账号不会因新授权被自动启用。
- [ ] 每个导入项分别显示成功、失败或待确认；已成功项保留，失败项可单独修正重试，未知结果先查询。
- [ ] 整批成功数不代表整体配置生效；普通与 native 回执各自可追踪，取消不删已有成果。
- [ ] 使用混合成功、重复、冲突身份、禁用账号及丢响应的合成批次完成 HTTP／EgoLite 验收。
- [ ] 记录受影响行为的高层本地验证、必要的 EgoLite 产品验收与审查证据；静态存在、fixture、真实渠道和生产结论分开，结果使用 PASS／FAIL／NOT_RUN／BLOCKED。
- [ ] 保留账号／渠道／权限及数据边界；涉及权威管理契约时单向同步生成客户端，遵守既有前后端归属与跨边界记录；必要 ADR 与相关陈旧测试入口随本切片修正。
- [ ] 在实际 checkout 上复核范围，完成适用 Task／Phase 门槛；本票不自动授权真实账号、收费请求、服务变更或部署，具体外部操作以已明确目标和范围为准。
