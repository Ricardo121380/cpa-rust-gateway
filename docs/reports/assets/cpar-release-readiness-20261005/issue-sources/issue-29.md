## What to build

三协议流式工具参数和并行调用保持完整配对，调用方的并行／串行控制被遵守或明确拒绝。

实施编号 CPAR-20；实施批次：B。覆盖用户故事 56, 57, 58, 59, 63, 66；验收场景 T08, T09, T10。

## Acceptance criteria

- [ ] 工具参数跨任意合法分片后正确重组；未完成或非法参数不得呈现为可执行调用。
- [ ] 已声明并行能力的路径覆盖多个调用及交错增量，ID、名称、参数与结果不会串线。
- [ ] 并行 true／false 及工具选择进入真实准入和上游表达，不能固定为未请求并行或静默忽略串行约束。
- [ ] 未声明或目标无法表达的并行／选择请求明确拒绝；拒绝正确不等于该能力受支持。
- [ ] 公共 SSE 与受控上游完成工具结果回传及后续多轮，覆盖中断、非法分片和唯一终态。
- [ ] 记录受影响行为的高层本地验证、必要的 EgoLite 产品验收与审查证据；静态存在、fixture、真实渠道和生产结论分开，结果使用 PASS／FAIL／NOT_RUN／BLOCKED。
- [ ] 保留账号／渠道／权限及数据边界；涉及权威管理契约时单向同步生成客户端，遵守既有前后端归属与跨边界记录；必要 ADR 与相关陈旧测试入口随本切片修正。
- [ ] 在实际 checkout 上复核范围，完成适用 Task／Phase 门槛；本票不自动授权真实账号、收费请求、服务变更或部署，具体外部操作以已明确目标和范围为准。
