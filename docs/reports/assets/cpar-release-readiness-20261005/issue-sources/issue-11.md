# #11 CPAR-02：同流程核对并应用待生效修改

State: OPEN; Updated: 2026-09-29T13:26:50Z

## Parent

[实施规格 #9：CPAR 现有渠道可靠性与管理体验收敛](https://github.com/Ricardo121380/cpa-rust-gateway/issues/9)

## What to build

接入或管理动作提交时，自动处理没有旧修改的情况；有旧修改则核对完整清单后应用，也可保留待应用。

实施编号 CPAR-02；实施批次：A。覆盖用户故事 13, 14, 15, 16, 17, 18, 52；验收场景 T03, T04。

## Acceptance criteria

- [ ] 从一个真实普通账号导入／管理动作演示无旧修改时保存、校验、自动发布及分阶段反馈。
- [ ] 有旧修改时展示旧修改与本次修改的合并清单，明确选择应用或保留；不得静默夹带旧修改。
- [ ] 核对后活动版本或 revision 变化时重新读取与核对；不能用旧清单覆盖并发修改。
- [ ] 校验失败保留已保存事实；普通配置发布保持原子性及原有效快照，不把独立凭据更新说成已回滚。
- [ ] HTTP 受控冲突与丢响应、EgoLite 清单核对／保留／恢复路径通过，权限不自动扩大。
- [ ] 记录受影响行为的高层本地验证、必要的 EgoLite 产品验收与审查证据；静态存在、fixture、真实渠道和生产结论分开，结果使用 PASS／FAIL／NOT_RUN／BLOCKED。
- [ ] 保留账号／渠道／权限及数据边界；涉及权威管理契约时单向同步生成客户端，遵守既有前后端归属与跨边界记录；必要 ADR 与相关陈旧测试入口随本切片修正。
- [ ] 在实际 checkout 上复核范围，完成适用 Task／Phase 门槛；本票不自动授权真实账号、收费请求、服务变更或部署，具体外部操作以已明确目标和范围为准。
