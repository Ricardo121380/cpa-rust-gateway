## Review conclusion

The new runtime view consumes exactly `anthropic.messages.max_tokens` only when it is a positive
JSON integer and no `openai.responses.max_output_tokens` target already exists. It rebuilds the
extension map deterministically, removes the source field, and inserts the target field unchanged;
all other namespaces remain in the map for `provider-openai-compatible` to reject. This preserves
the upstream output bound without relaxing the generic foreign-extension rule.

The review also verifies the translation is performed before `CredentialLease::secret_bytes()`.
Therefore malformed/colliding request state cannot open an encrypted Bearer, construct an outbound
request, dial an endpoint, or cause a retry. The source change adds no endpoint, credential,
proxy, redirect, listener, route, retry, or public-traffic behavior.

The first implementation used a test-only direct `protocol-anthropic` dependency in `gateway`.
The crate-boundary gate correctly rejected it before any commit or artifact. The final regression
uses the already-approved Canonical representation while the protocol crate's own fixture test
proves the source representation; the direct dependency and lock-file change were removed. The
full rerun passed all 21 crate boundaries. No source-level blocker remains.
