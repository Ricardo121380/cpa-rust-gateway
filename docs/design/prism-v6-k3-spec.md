# Prism Liquid Glass V6 · 设计规格

日期：2026-09-10。状态：**V6 交互样稿已交付，正式前端尚未实施**。

对应文件：`prism-liquid-glass-v6.html`（自包含单文件，双击可开；首次进入为登录页，任意非空密码进入样稿）。本文档是把它迁移到生产 React（Vite / TanStack Query / Zustand，4 个静态构建文件，同源 `/admin/*`，CSP 禁 inline）所需的规格。V3–V5 文件全部保留，未改动。

## 1. 为什么改结构（V5 → V6）

V5 被否定的不只是配色，而是构图本身：一个大外框里放一排等高盒子，指标、状态、入口全是同尺寸卡片，没有信息层级；资源主名称直接使用 `p12-xx-service-*` / 32 位哈希，且成对重复。V6 的两条主轴：

1. **编辑式分节替代卡片阵**：内容画布是一张实底 sheet，内部用发际线划分横向分节（band），每节内部再按内容选择布局——总览是不对称 7:4 分栏（左：待处理队列；右：当前配置 + 资源索引），账号池是渠道分组表格，模型与路由是 340px 列表 + 工作台双栏。一个页面内不允许出现两个以上同尺寸并列卡片。
2. **统一资源命名系统**：见第 4 节。列表与标题只出现友好名称 + 渠道/类型 + 短标识；完整 ID 收敛到详情面板与复制操作。

材质预算不变：顶栏 / 侧栏 / 草稿坞最多三面 chrome 玻璃（PrismLens 折射），内容永远实底，不给行、卡片、小组件加模糊。

## 4. 友好名称规则（核心约束）

界面中任何资源对象的显示身份由三部分组成，**顺序固定**：

```
友好名称          渠道 / 类型            短标识
Atlas 生产号  ·   Grok Build · OAuth  ·  [ac-7f2a]
```

1. **友好名称**是主名称（管理员起的显示名）；列表、标题、引用处一律用它。
2. **渠道/类型**用 chip 或次级文字表达（Grok Build / ChatGPT Codex / Claude / 兼容 API；OAuth / Session / API Key）。
3. **短标识** = 资源类前缀 + 4 位辨别码（`ac-` 账号、`up-` 上游、`ep-` 端点、`cr-` 凭据、`rt-` 路由、`cd-` 候选、`gp-` 访问组、`key-` Client Key、`eg-` 出口策略、`px-` 代理池、`req-` 请求、`ev-` 事件、`snap-` 目录快照、`pc-` 价格目录）。等宽字体小徽章，hover 显示复制图标，**点击复制完整原始 ID**。短标识只做界面辨别，不是 API ID，不参与任何请求。
4. **完整原始 ID**（`p12-prod-service-<kind>-<32hex>`）只出现在详情检查面板的「完整 ID」行和复制结果中；不从友好名称反向推导，不把显示规则回写到 API。
5. **不简单去前缀**：`up-`、`ep-`、`cr-` 前缀本身就是类型信息，去掉会导致不同资源混淆；成对重复展示（标题一次、副标题又一次）被禁止——同一视图同一对象只出现一次短标识。
6. **模型名是协议 exact ID**（`gpt-5.5`、`grok-4.6`、`claude-sonnet-4.5`），作为主名称原样等宽展示，不美化、不改写；别名是独立配置对象，只指向 exact ID。
7. **账号多绑定**：账号 = 认证身份；绑定 = 账号 × 端点 × 凭据 的配置关系。列表按渠道分组，详情用「绑定与凭据」分页列出全部绑定（样稿中 Vega 备用号有 2 个绑定）。绑定、认证、调度是三个独立口径，界面文案明确「绑定正常不代表可调度」，不合并为健康分。

## 5. 组件结构

- **chrome（玻璃，≤3 面）**：顶栏（品牌 / 面包屑 / 配置上下文胶囊 / ⌘K / 主题 / 账号）、侧栏（3 组 14 栏目 + 计数）、草稿坞（仅草稿态出现：版本、rev、变更数、校验、发布）。配置上下文胶囊是当前「查看已发布 v24 ↔ 编辑草稿」状态的唯一全局指示，点击进入配置版本。
- **sheet**：实底内容画布，内容滚过顶栏时顶栏阴影加深（`data-over`）。
- **readouts**：发际线分隔的指标带，第一项可为 hero 大数字；只允许真实可得指标（见第 7 节）。
- **q-row 待处理队列**：severity 点 + 标题 + 一句上下文 + 深链，按严重度排序；异常与未完成计费永远在此可见，不可隐藏。
- **i-row 资源索引**：名称 + 计数 + chevron 的密集链接列表，替代 V5 的入口卡片。
- **表格**：无底色表头 + 发际线；行高约 62–66px；首列 entity = 渠道字标 + 名称 + 短标识；行点击与 chevron 按钮打开右侧检查面板。
- **sid 徽章**：短标识 + hover 复制图标，点击复制完整 ID（clipboard API，失败则弹出完整 ID 对话框）。
- **检查面板 inspector**：右侧 520px 实底面板，非玻璃（内容材质与导航统一为实底体系，玻璃只留给 chrome）；标题区 = 字标 + 名称 + 渠道 + 状态徽章组 + 完整 ID 行；正文分页签或分区；Esc / 点击遮罩关闭，焦点返回触发元素。
- **modal**：居中，仅用于表单与确认（发布、回滚、启停、退出登录、密钥一次性回显）。
- **草稿工作流**：默认查看已发布配置（只读 + 提示条）；任何编辑动作先经「在草稿中编辑」确认进入草稿；编辑只改草稿（dock 出现，chrome 材质变 draft，修订数 +1）；校验、发布各自居中确认；回滚是另一个独立确认。已发布 ≠ 运行快照热更新，程序部署另行进行——此说明固定出现在配置版本页。

## 7. 数据语义红线（样稿已遵守，生产必须保持）

- 只有进程累计 attempts、成功/总 attempts、已处理事件、账本完整性四类指标；**不伪造**请求趋势、延迟分析、请求级成功率。
- null = 未观测：显示「未观测」或 —，不按零计入、不推断、不合成；权益为 null 不当作 Free。
- 认证、调度、权益、目录新鲜度分开呈现；目录模型计数 ≠ 授权可调用数。
- 六类 token（输入/输出/推理/缓存读取/缓存创建/缓存合计）各自保留置信度（权威/推导/声明），互不合并。
- 账本为空不推断没有消费；修复期间记录保持可见。
- 界面默认精简解释文字；口径集中在「观测口径」「目录口径」弹层与详情面板；**异常与未完成计费不可隐藏**（总览队列 + 计费横幅双重出现）。

## 8. 响应式与辅助偏好

- 断点：1200（收窄侧栏/指标带 2 列/工作台 300px）、820（侧栏转浮层、账号表转卡片、检查面板 12px 内缩）、560（壳边距 12px、面板与对话框左右各 12px、表单与确认始终居中）。页面画布任何宽度无横向滚动；长表只在自身容器内滚动。
- 1280×720：侧栏行高压缩（32px），14 栏目全部可见无需滚动。
- 浅色/深色：顶栏图标或设置页切换，内存态不落盘。
- 辅助：`prefers-reduced-transparency` / `prefers-contrast:more` / `prefers-reduced-motion` 媒体查询与设置页手动开关双通道（后者写 `data-*` 属性）；降级时玻璃变实底、grain 关闭、退火 0ms、边框加强；降级规则的选择器特异性与透镜规则持平（`html[data-*] .glass[data-pane]`），不会被折射层压过。`forced-colors` 有基础适配。
- 键盘/焦点：全键盘可达，`:focus-visible` 2px tint 描边；Esc 关闭浮层；对话框关闭后焦点返回触发元素；⌘K 栏目跳转；`aria-current` / `aria-selected` / `aria-checked` / `aria-pressed` 齐全。

## 9. 样稿边界

- 全部为合成数据；导航、主题、筛选、搜索、详情、表单、草稿→校验→发布→回滚流程可实际操作，写操作只改会话内预览状态。
- 不启动真实授权、不发 Provider 请求、不执行恢复/回滚/备份；此类操作在界面中明确标注「样稿」。
- 目录口径、Route Explain、Channel Pin、差异、备份预检为固定设计样本并就地标注。
- 已验证：`node --check` 通过；1440×900 总览渲染检查通过（发际线分节、非对称分栏、玻璃 chrome 正常）。未逐页截图验收其余 13 栏目与移动端/深色组合，正式实现前仍需 F0–F4 验收。
