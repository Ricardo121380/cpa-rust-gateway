## 5. 本轮后端必须补齐的能力

### BE-FE-01：管理鉴权下的有效模型与来源投影

复用数据面的授权和模型可见性逻辑，以同一份 serving snapshot 提供管理侧只读投影。输入按既有 Client Key ID 或 Access Group 选择授权上下文，不要求浏览器提交 Client Key secret，也不以 Management Key 冒充数据面 Key。

结果应足以支持 exact model 选择和来源说明：实际可见模型、配置/目录/Provider/channel/endpoint/credential 的安全标识、serving 版本或快照、观测时间，以及必要的歧义/不可选原因。具体字段沿用已有模型，避免建立第二套授权判定。

验收：同一配置和授权上下文下，管理投影与数据面模型可见性一致；权限不同的两个上下文返回各自集合；草稿配置不会冒充正在服务的集合；未授权模型和秘密不泄漏。缺少某个渠道的观测保持真实 Missing，不为本轮扩展全部渠道 discovery。

### BE-FE-02：完整配置枚举与候选维护

Route 已有读取/修改/删除接口，优先复用。新增完整、版本一致且有界的 Route/Candidate/Alias 读取；涵盖未绑定、孤立和仍在编辑的草稿资源，不能从运营 inventory 推断完整配置。

补齐候选修改/删除或语义等价的明确集合操作，保留 config version、If-Match、引用/结构校验和审计。前端将已有模型/路由能力与新增接口结合，而非重写整个配置系统。Alias 本轮包含完整读取与已有创建能力，不自动扩展其他未约定的管理功能。

验收：创建未绑定草稿资源后可列出；修改/删除候选后刷新和重启仍一致；旧 revision 被拒绝；跨页读取不会拼接不同 revision；被引用/不可删除资源有明确错误及修正路径。

### B1/B2：真实计费与有界运营读取

在 `serve` 组合根接入可停止、有批量上限的物化 worker，按已持久化事件的 ordinal/checkpoint 增量处理，复用既有计价和幂等逻辑。耗时 SQLite 工作进入适当的 blocking 边界，请求处理不等待计费。明确坏记录的可追溯处理方式，避免永久卡住或静默丢弃。

提供最小的安全处理状态，如观测水位、待处理程度和安全失败分类，使 UI 可区分未启用、尚未处理、滞后、失败和真实空账本。这是本轮 BE-FE-03 的处理状态子集；请求级趋势与延迟统计仍在下一期。

把时间、身份、snapshot 上界和游标下推到存储查询；账本批读整行，消除 N+1。Usage/失败关联采用有界查询或必要的增量投影，保持计数、置信度与完整性；不靠增大 100,000 常量、截断结果或前端多次查询拼接绕过规模限制。迁移/索引若有必要，遵循现有版本与兼容机制，用合成数据验证成本。

验收：本地受控请求后生成对应账本；重复消费/重启不产生重复账本或金额；无价格写入 `unpriced`；可观测滞后/失败。覆盖 99,999、100,000、100,001 及更大样本，窄时间窗仍可查询，摘要与分页同一 snapshot，缺少必要证据时不伪报完整。

### B3/B4：目录硬过期与既有 TTL 维护

目录准入证据携带必要的硬过期信息，使用可控/统一时钟在新选择或租约边界拒绝到期证据；路由热路径不读取 SQLite，不通过频繁 Provider 调用解决失效。worker 发布时重新取时间，并在适当 deadline 处理失效发布；已有在途请求保持既有快照语义。

为 Stored Responses/compaction 等**已定义 TTL** 的存储接入单一、可停止、有批量上限的维护 owner，保留有效 continuation。账本清理仅在现有 retention 合约明确时按原约定接入，不自行制定新删除策略；事件日志和价格历史不纳入通用清理。

验收：跨过硬过期时间后，即使 discovery 失败也不能新租用过期证据；推进测试时钟只清理合约已到期记录；重启恢复、锁竞争及失败均有可核对的结果。所有删除验证仅使用本地合成数据。

## 6. 始终保留的约束

- 账号认证、调度、quota、权益与目录分别表达；不合成为 overall health。权益保留 domain/tier/source/confidence/observed_at，null 是未观测，不映射为 Free。
- exact model 来自真实后端投影，不硬编码模型白名单或套餐到模型的映射。目录计数不等于授权可调用数量。
- 运营跨版本读取、版本配置读取和带版本的 action 分别标识。页头版本选择不暗示所有数据都按同一版本过滤。
- 六类 token 各自保留观测/缺失与置信度；累计 attempts 不改名为请求成功率，空账本不等于零消费。
- 已导入受支持账号的日常续期属于 CPAR；初次授权、交互重授权、注册/补池属于 operator/Autoreg。本轮不构建 Autoreg 控制面或扩展全部渠道适配。
- 保留同源管理边界、统一 generated client、CSP、会话内秘密、四文件嵌入和当前技术栈；不新增浏览器秘密持久化、跨 listener 绕行或未经约定的外部依赖服务。
- 不为本轮做无关大文件重构、依赖升级、全量英文、在线备份恢复、秘密导出、未支持媒体协议或真实 Provider 自动批量巡检。

## 7. 验证与完成定义

每个实现批次运行受影响检查；M4 汇总一次完整验收。已有审查的 77 个后端定向测试、229 个前端测试和 V4 原型检查是历史基线，不作为新实现通过的证据。

### 必须有的用户路径证据

1. 解锁 → 版本 A/B 切换 → 旧响应晚到；当前版本与 revision 不被污染。
2. 会话被拒绝 → 停止轮询并清除秘密/受保护缓存 → 返回解锁；普通 404 保持资源错误。
3. 账号筛选 → 详情权益 → 目录/失败 → target/Explain → 返回原筛选；null、missing、expired 和多权益域准确呈现。
4. 选择授权上下文 → 查看 effective models → 选择 exact model → 编辑草稿 Route/Candidate → 校验 → 发布 → 重新读取配置/审计；包含冲突和失败分支。
5. 新候选修改/删除、孤立草稿枚举和已有上游/访问组/Key/出口配置操作持久化，刷新后不靠前端内存维持“完成”。
6. loopback mock Provider 受控请求 → 持久事件 → 计费物化 → 账本/用量/失败界面读取；计价、未定价、重启幂等和处理状态分别可核对。
7. 大样本窄窗查询、目录硬过期、TTL 维护在受控时钟/数据下通过，不访问生产库或真实 Provider。

## 8. 排期与范围管理

前期方案的 13–18 个有效工作日只覆盖已有接口范围的前端收口，不包含本次确认的后端补齐，不能作为本轮全栈承诺。M0 完成后，根据契约、存储迁移和测试基线更新估算；本轮不设未经用户指定的 token 预算或截止日期。

主要风险集中在授权投影与数据面一致性、有界运营投影、物化重放/坏记录策略，以及真实管理 listener 验收。优先用契约和受控测试消除这些不确定性，再扩大页面接线；不通过扩大 Goal 范围解决与本轮无关的 P13 未完成事项。

生产发布不属于本 Goal 的完成条件。若后续用户要求部署，先准备具体 artifact、验证与回滚方案，再按该次授权处理目标环境。
