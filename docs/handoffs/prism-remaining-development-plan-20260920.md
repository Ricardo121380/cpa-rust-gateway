## 4. 设计与实现约定

### OpenDesign 与设计规范

- 沿用项目 `prism-gateway-console-redesign-a735`，新增本轮产物，不覆盖历史设计。
- 指定 Pi → `cc-switch-kimi-for-coding/k3:max`。2026-09-20 只读预检确认 OpenDesign 0.22.2 服务、既有项目和 Pi/K3 实时模型列表存在；Codex MCP 接入状态为未安装，当前会话没有可调用工具。实施前使用当前服务提供的配置恢复接入，验证项目读取与实际 max 映射，再验证模型调用。未调用前不声称额度或认证可用。
- 先设计账号与授权、提供商详情与编辑、价格目录编辑与预览三类代表场景，覆盖桌面、手机、深浅主题及关键错误态；经 C2C 复核后推广到其余栏目。
- 输入使用合成数据和当前操作约束，不发送真实账号、凭据或生产数据。旧 K3 样稿的短编号、旧导航和旧统计说明不作为行为标准。
- 应用 frontend-design、ui-ux-pro-max、vercel-react-best-practices；统一系统字体、银白/石墨灰/Apple 蓝、紧凑间距、44px 触控目标及可读对比度。导航、浮层和内容材质连贯，保留深浅色、降低透明度和减少动效。
- 页内工作区、表单和抽屉复用操作生命周期。同一时刻只有一个主要操作和一个导航阻止器；确认步骤不引入竞争的路由 blocker。原型不直接复制进生产入口。

### 待应用与结果恢复

- 高级操作首次提交时复用明确选中的草稿；当前为活动配置时，从核对过的活动配置建立工作草稿。进入页面或取消空表单不创建草稿。
- 保存成功后进入统一待应用上下文，展示业务变更摘要；后续配置修改加入该批。主操作为“查看变更”和“校验并应用”。
- 应用前重新核对草稿修订、活动配置和发布条件；并发冲突不自动重放。
- 分别呈现已保存待应用、已应用、部分保存、结果待核对。保留精确恢复目标，不确定结果只允许安全重读和核对。
- 未保存离开需丢弃确认；写入期间禁止关闭、渠道切换和导航。会话失效清理秘密、轮询和缓存，不混淆服务端已保存事实。
- 刷新/重新登录后通过服务端读取待应用记录，由管理员明确继续；不持久化浏览器秘密，不默认选择任意草稿。

### 重点修复

- Provider 顶层、高级访问组、出口 Pool/Node/Binding 和删除操作接入稳定动作区、busy、明确结果及服务端重读。
- 不允许新配置未支持的访问组限额。历史非空值只读呈现并解释限制，提供明确清除或停用动作；不自动清空，不以草稿保存成功暗示限额可运行。
- 复杂价格编辑迁入页内，复用已有 billingTask/回执逻辑。完整条目及差异每页 50 条，可遍历全部允许条目；预览冻结提交内容，六类费率保留原值和未知状态。
- 目录写入继续遵守现有鉴权/CAS。导入/恢复前确认全局影响和生效时间；入库成功明确显示全局已保存。策略绑定和工作配置结果单独表达，不改写历史账本。
- 复杂出口配置、批量差异、路由及多步骤配置进入页内；简单新增/危险确认沿用统一表单。保持引用检查、精确目标和非重放恢复。
- 所有工作区统一加载、空态、错误、重读、筛选、长内容及详情；请求数与 attempts 分开，未观测值不补零。

### 接口与数据

本轮不计划新增公共 API 或数据库迁移，复用 CRUD、配置复制/校验/发布、目录分页和权限接口。内部新增/整理工作区组件、操作上下文与结果展示。

若出现完成已确认流程所必需的契约缺口，先写具体 CR，由 Codex 定稿后端与权威 OpenAPI，再 sync-contract 生成客户端；不手改生成物。保持 React/Vite、TanStack Query、Zustand、同源 `/admin/*`、CSP 和四文件构建。跨边界实现提交同时更新日志与 Cross-Boundary trailer。
